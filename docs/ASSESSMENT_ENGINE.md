# Engine reference

`shared/modules.ts` is the versioned public registry. Each entry has ID, category, renderer family, instructions, estimated seconds and adaptive flag. Plans contain ordered blocks `{ moduleId, rounds }`; `locate()` maps the global response cursor to its block and local round. Comprehensive and Extended use two/three passes, making consistency/retention comparisons occur much later.

`generate(seed, plan, index, difficulty)` returns `{ challenge, answer }`. Its stable PRNG is not cryptographic; secrets use Node crypto instead. A challenge contains its global index, module, renderer, difficulty, prompt, bounded stimulus data and response budget. The API sends only `challenge`. Timing trials necessarily expose stimulus schedules in the browser; this is light anti-cheat entertainment.

`grade(challenge, expected, answer)` returns 0–1. Memory grids penalize excess selections; sequences compare positions; estimation/interval use relative error; target detection penalizes false positives; precision grades distance; multitasking weighs arithmetic 40%, alerts 30%, time in range 30%; typing compares displayed characters; discrete tasks match a generated answer. Skips/false starts score zero. Confidence is captured before most discrete submissions; immediate response tasks use the default confidence and do not interrupt timing.

Adaptive blocks begin at difficulty 2 (range 1–8). Three scores >=.85 increase difficulty; two of the last three below .5 decrease it. Only the current block’s latest responses affect progression. Difficulty is recorded before every answer. Delay/exposure/span/layout complexity vary with difficulty where meaningful. Decision preferences, typing and interval tasks stay fixed in difficulty.

Responses require a current issued challenge and the expected index. The API validates bounded answers, inserts `(session_id, trial)` uniquely, and advances inside one transaction. Already-accepted indices are acknowledged without advancing again. Client drafts are local; a failed submission retains its complete answer for retry. Pausing clears an unsubmitted timing origin. Server elapsed estimates include actual challenge issue-to-submit time (bounded at ten minutes per trial); reaction measurements use client `performance.now()` relative to stimulus onset, not network latency.

Calculated metrics and released display snapshots are separate. `resolve(real, override)` makes a deep copy, then merges only configured values/category keys/labels. Presets are server-only starting templates; editable result profiles persist in the database. Invite tokens are HMAC-hashed and atomically claimed. A profile is snapshotted at start so future edits do not surprise an active session.

Release snapshots the resolved display, preserving real metrics. Manual/delayed reveal reveals real values only after activation/time. Every released report has a 24-hour disclosure fallback. Before release the participant result API returns only `{ held:true }`; before disclosure no real-result object is returned. Full genuine metrics remain available to authenticated operators throughout.

Limitations: this is not a standardized test. Browser scheduling, input hardware, task mix, practice and difficulty affect measurements. Switch cost is an observed mean changed-rule vs repeated-rule latency difference, not a controlled clinical estimate. Typing accuracy uses character positions; an early insertion can penalize subsequent characters. Decision scores quantify consistency within expected-value groups, not whether a person chose a “correct” risk preference. Performance change is not a fatigue diagnosis.
